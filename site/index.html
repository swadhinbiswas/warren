what makes it different

Why Warren?

Run the same app many times with different accounts, configs, and data. Nothing leaks between instances.

Total Isolation

Each instance gets its own HOME, config, cache, data, and tmp directories. Nothing leaks between instances.

Unlimited Aliases

Install the same tool as many times as you want with different names. gh-work, gh-personal, gh-side.

GUI App Wrapping

Run two Discords, two Firefox profiles, two VS Code instances — each with separate logins and data.

Rootless by Design

Warren refuses to run as root. No sudo, no daemons, no containers. Just a thin bash launcher.

Zero Overhead

No VMs, no containers, no background processes. Startup overhead is under 50ms.

Universal Shell

Works with Bash, Zsh, Fish, and Nushell. Auto-detects and configures your PATH.

under the hood

How it Works

Three simple levers achieve total isolation without kernel namespaces or OverlayFS.

1

Intelligent Rewriting

Warren intercepts installer scripts and rewrites hardcoded paths like /usr/local/bin or ~/.config to point inside the instance's private directory.

2

Environment Injection

A lightweight launcher overrides $HOME, $XDG_CONFIG_HOME, and $TMPDIR before running your tool.

3

Execution

The application boots entirely unaware that its "home directory" is a sandbox inside ~/.warren/.

See it in Action

Two GitHub CLIs, two accounts, zero conflicts.

~

  Installed: gh-work
  Launcher: ~/.local/bin/gh-work
$ warren dig gh --as gh-personal

  Logged into github.com as @work-account
$ gh-personal auth login
  Logged into github.com as @personal-account
